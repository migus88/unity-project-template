# Changelog

All notable changes to this package are documented here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/) and the package uses [Semantic Versioning](https://semver.org/).

## [Unreleased]

### Added

- Scene-authored scope installers (`Core.Domains.ScopeInstaller`, an abstract `MonoBehaviour` implementing VContainer's `IInstaller`): a `DomainLifetimeScope` runs the installers listed in its new `_installers` field after `ConfigureDomain`, so a game that re-skins a foundation domain with its own scope scene can register its own scene components there. An empty slot throws `InvalidOperationException` naming the scope and index. Existing scopes are unaffected (the field defaults to empty).
- UI click tracking seam (`Core.Analytics`): a `UiClickRelay` on a scope scene's canvas root carries an authored `Screen` id; clickable widgets call `UiClickRelay.Emit(this, elementId)` (ignored for an empty id or without an ancestor relay), and `builder.RegisterUiClickTracking(relay)` forwards every `UiClick(Screen, Element)` to the root seam `IUiClickTracker`. A game implements the tracker (typically turning clicks into an analytics event); `RootLifetimeScope` registers `NullUiClickTracker` when the game registers none. Foundation widgets and domains do not emit clicks yet.
- `SettingsArgs.From` (default `"unknown"`): the opener of the Settings screen. `SettingsPresenter` tracks `settings_opened {from}` (`Settings.Analytics.SettingsOpenedEvent`) once when Settings opens; its constructor takes the `SettingsArgs`.
- Crash context (`Core.Diagnostics`, registered by `CoreInstaller`): domains publish the file of the current session through `ICrashContext.SetSessionFile(storagePath)` (relative to the `IFileStorage` root; rooted or empty paths throw `ArgumentException`) and `ClearSessionFile()`; crash reporters read the concrete `CrashContext` (`SessionFilePath`, `SessionFileName`, `LogFilePath` = `Application.consoleLogPath`, and `ReadLogTail(maxBytes)`, which returns the last bytes of the log starting after a line break, `NotFound` when there is no log and `Error` on IO failures, reading while Unity keeps the log open). Reads and writes are safe from any thread, so reporters can call them from their send hook.
- Consent leaf domain (`Consent`, scene `Domains/Consent/Scenes/Consent.unity`): the first-launch privacy prompt ("Help improve the game", Yes/No, a close button, Escape = No, a "Privacy policy" button shown only when the policy has a URL). Yes grants and No, close or Escape deny the current policy version through `IConsentService`; `consent_granted {policy_version}` (`Consent.Prompt.ConsentGrantedEvent`) is tracked after the grant, nothing on a denial. `ConsentDomain.IsPromptNeeded` tells a main flow to await `RunAsync` before its first screen (the template sample does). `RootLifetimeScope` registers the domain from a new `_consentDescriptor` field, assigned on the package root prefab; a game root prefab variant that overrides it must keep it assigned. Own localization table (`ConsentText`) and test assembly (`Consent.Tests`).
- `PrivacyPolicy.CurrentVersion(IRemoteConfigService)`: the higher of the built-in version and the remote `privacyPolicyVersion` flag, read at call time. The consent prompt and the Settings Privacy row grant and deny with it (`Settings.Privacy.PrivacyPresenter` takes an `IRemoteConfigService`).
- Settings Privacy row (`Settings.Privacy`): a Yes/No selector bound to `IConsentService` (either arrow flips it; Grant/Deny use the current policy version and save at once, independent of Back), a "Privacy policy" button that opens the policy URL (hidden when none is published), the install id in a read-only, selectable `TMP_InputField` ("None" before the first grant) and a hint on requesting deletion. Each toggle tracks `consent_changed {granted, source=settings}` (`Settings.Privacy.ConsentChangedEvent`). The Settings domain gets its own localization table (`SettingsText`), `Settings.asmdef` references `Unity.TextMeshPro`, and the new `Settings.Tests` assembly covers the row and the scene wiring. `TestUtils.FakeConsentService` (with `R3.dll` added to `TestUtils`) mimics the consent service's install-id rules.
- `Core.Privacy.PrivacyPolicy(Url, Version)`: the current privacy policy, built by `PrivacyPolicy.From(BuildEnvironment?)` (version raised to at least 1; a URL that is not an absolute https URL is dropped with a `Privacy` warning; no environment gives `PrivacyPolicy.Unpublished`, no URL and version 1). `RootLifetimeScope` always registers it, so domains inject it instead of the optional `BuildEnvironment`.
- `IApplicationService.OpenUrl(string)` wraps `Application.OpenURL`. Implementers of `IApplicationService` must add `OpenUrl`.
- Platform contracts (`Core.Platform`): `IAchievements` (`Unlock`, `ReportProgress`, `GetStatus` returning `AchievementStatus` Locked/Unlocked(UnlockedUtc)/Unavailable; fire and forget, platform failures are logged, never thrown; progress on an unlock-only achievement or below 0 throws `ArgumentException`, checked by `AchievementArguments.ValidateProgress`) and `IPlatformPresence` (`Set(Presence(Token, Values))`, `Clear`). `Achievement` (snake_case id up to 64 characters, `ProgressTarget`, 0 = unlock-only) and `AchievementCatalog` (validated list, throws on duplicate ids; `Empty`). `AchievementIdMap` maps catalog ids to platform ids: identity by default, per-platform overrides replace the id (the game id then no longer maps back), `FindProblems` reports overrides for unknown ids, blank platform ids and two achievements on one platform id, and the constructor throws on any. `RootLifetimeScope` registers `NullAchievements` (status `Unavailable`, same argument checks), `NullPlatformPresence` and `AchievementCatalog.Empty` when the game registers none; implementers register both interfaces from the game module or a platform installer.
- Editor reporting rule (`Core.Environment.ReportingRule`, registered by `CoreInstaller`): `IsReportingAllowed` is true in a player and, in the Editor, only while the one-Play-session override is armed (`IsEditorOverrideActive`); every sender (telemetry, crash reports, uploads) ANDs it into its gate next to consent and the `BuildEnvironment`. `IReportingOverride` is the seam over the override; the Editor API is `Core.Editor.Environment.EditorReportingOverride` (`IsEnabled`, `SetEnabled`; arming during Play throws `InvalidOperationException`), stored in `SessionState` and cleared when the Editor enters Edit mode.
- Remote config (`Core.RemoteConfig`): `IRemoteConfigService.Get(flag)` answers typed flags (`BoolFlag`, `IntFlag`, `NumberFlag`, `StringFlag`: key plus compiled default; the first ones in `CoreFlags`: `telemetryEnabled`, `recordingUploadEnabled`, `privacyPolicyVersion`). Layers, highest first: the server document, the `BuildEnvironment`'s `RemoteConfigDefaults`, the compiled default; a value that does not parse as the flag's type falls through and warns once per key. `CoreStartup` loads it once, alongside settings and consent: it reads the `remote-config.json` cache (ignored when corrupted, of another version or of another environment), then sends `GET {TelemetryEndpoint}/v1/config?build=&platform=` with `If-None-Match` and a 3 s timeout (`RemoteConfigService.FetchTimeout`). `200` replaces the values and the cache, `304` keeps the cache, `404` drops it, network errors, timeouts, other HTTP errors and invalid documents keep it. Nothing is fetched without a `BuildEnvironment` or endpoint. `CoreInstaller` registers it (concrete `RemoteConfigService`); `CoreStartup`'s constructor also takes a `RemoteConfigService`. New log tag `RemoteConfig`.
- Telemetry (`Core.Telemetry`): `builder.RegisterTelemetryBackend()` registers an HTTP `IAnalyticsBackend`, so `RootLifetimeScope` skips `DummyAnalyticsBackend`. It sends while consent is granted, the `CoreFlags.TelemetryEnabled` remote flag is on (read at use time; when off, nothing is queued or sent and the queue file is kept) and the registered `BuildEnvironment` allows telemetry with an endpoint (and the build version matches the server's `major.minor[.patch][-suffix]` pattern; otherwise it logs an error and stays off). Events are validated as they are tracked (snake_case names and keys, at most 64 props, strings cut to 256 UTF-8 bytes, finite floats; invalid ones are dropped with an error), stamped with a per-session `seq` and a Unix-ms `time`, queued under an envelope (install and session id, build, platform, environment, policy version) and mirrored to `telemetry/queue.json` (version 1, at most 2000 events, oldest dropped first and reported as `telemetry_dropped`). Batches of up to 250 events (and 900 KiB of JSON) go gzipped to `<TelemetryEndpoint>/v1/events` with `X-Ingest-Key` every 15 s, when `AnalyticsFlushSignal` is raised and on quit; 429, 5xx, timeouts and network errors retry with backoff (15 s doubling to 10 min, or `Retry-After` when longer), other 4xx drop the batch with an error. Leftovers are sent on the next launch under their original envelope; withdrawing consent clears the queue and deletes the file. The pipeline tracks `session_started` and `session_ended {duration_s}` itself. New log tag `Telemetry`.
- `Core.Analytics.AnalyticsFlushSignal` (registered by `CoreInstaller`): `Request()` asks the analytics backend to send what it holds; `DomainRunner` requests it when a domain starts and when it stops.
- `IApplicationService.AddQuitHandler(Func<CancellationToken, UniTask>)` (returns an `IDisposable` that removes it) and `QuitBudget` (2 s): on quit, every handler runs at once with a token cancelled when the budget runs out; players delay quitting until they finish, the Editor runs them without waiting. A handler that throws is logged and the others still run. New log tag `Application`. Implementers of `IApplicationService` must add both members.
- Unobserved UniTask exceptions (`UniTaskScheduler.UnobservedTaskException`, e.g. from `.Forget()`) and unhandled AppDomain exceptions are forwarded to `Log.Exception` by a root entry point (`Core.Logging.UnhandledExceptionForwarder`) registered in `CoreInstaller`; `OperationCanceledException` is ignored. Crash reporters that listen to the Unity log see them.
- Build environments (`Core.Environment`): `BuildEnvironment` assets hold per-environment values (`EnvironmentName`, `IsTelemetryAllowed`, `TelemetryEndpoint`, `TelemetryIngestKey`, `CrashReportingDsn`, `CrashReportingEnvironment`, `PrivacyPolicyUrl`, `PrivacyPolicyVersion`, string `RemoteConfigDefaults`), checked by `BuildEnvironmentValidation`. `RootLifetimeScope` has an optional `ActiveBuildEnvironment` slot field and registers the slot's `BuildEnvironment` instance when set (warns when the slot is empty). Editor: `Core.Editor.Environment.BuildEnvironmentMap` maps build profiles to a development and a release environment; a pre-build hook writes the active profile's environment into the slot and fails the build (`BuildFailedException`) when the profile is unmapped or the environment invalid; the slot is restored to the map's Editor environment after the build, on Editor load and before Play mode. Projects without a map build as before.
- HTTP (`Core.Http`): `IHttpService.SendAsync(HttpRequest, ct)` returns `HttpResult`: `Completed` (status below 400, including 304, see `HttpResponse.IsNotModified`), `HttpError` (400 and above, keeping status, body and headers such as `Retry-After`), `NetworkError` (connection, DNS or data-processing failure) or `Timeout` (the request's own `Timeout` elapsed, measured in real time). Cancelling `ct` throws `OperationCanceledException`; no other exception leaves the service for network or HTTP failures. `HttpRequest.Get(url, timeout, etag)` sets `If-None-Match`, `PostJson(url, json, isGzipped, timeout)` sends UTF-8 JSON (gzipped with `Content-Encoding: gzip` when asked), `PutBytes(url, bytes, contentType, timeout)`, and `WithHeader` returns a copy with an extra header. `HttpResponse` reads headers case-insensitively (`GetHeader`, `ETag`) and `ReadText()` as UTF-8. `CoreInstaller` registers it over `UnityWebRequest`; `TestUtils.FakeHttpService` records requests and answers with queued results. The package now depends on `com.unity.modules.unitywebrequest`.
- `Core.Compression.Gzip.Compress(byte[])` (`CompressionLevel.Optimal`), next to `Deflate`.
- Consent (`Core.Privacy`): `IConsentService` (registered by `CoreInstaller`, concrete `ConsentService`) holds the player's telemetry consent as an observable `ConsentSnapshot` (`ConsentState` Unknown/Granted/Denied, accepted policy version, install id), plus `IsGranted`, a per-launch `SessionId` that is never saved, `NeedsPrompt(currentPolicyVersion)` (Unknown, or Granted for an older policy; Denied never re-prompts), `GrantAsync` and `DenyAsync`. The install id is created on the first grant, kept on re-grant and regenerated when consent is withdrawn. Persisted in the new `privacy` settings section (version 1; consent stored as `"granted"`/`"denied"`), loaded by `CoreStartup` right after settings (its constructor takes a `ConsentService`); a stored grant without a policy version loads as Unknown. Editor and development builds get the `consent show|clear|grant|deny [policyVersion]` cheat (`Core.Privacy.ConsentCheats`, registered by `RootLifetimeScope`). New log tag `Privacy`.
- Analytics (`Core.Analytics`): code tracks `readonly record struct` events implementing `IAnalyticsEvent` (snake_case `Name`, `Write(IAnalyticsWriter)` with string/int/float/bool parameters) through `IAnalytics.Track<TEvent>` (generic over structs: no boxing). `CoreInstaller` always registers `IAnalytics`, forwarding every event to `IAnalyticsBackend`; runtime gating (consent, environment, Editor rule) is the backend's job. `IAnalyticsBackend` is the seam a real backend implements in the game module; `RootLifetimeScope` registers `DummyAnalyticsBackend` (logs `[Analytics] name {key=value, ...}` in Editor and development builds) when the game registers none. Foundation events: `cheat_used` (`Core.Cheats.CheatUsedEvent`, command name of every known cheat submitted to the console, no arguments) and `settings_changed` (`Core.Settings.SettingsChangedEvent`, one per field changed during a Settings visit, tracked on close; `Core.Settings.SettingsChanges.Diff` reports key bindings as `changed`, never their JSON). `TestUtils.FakeAnalytics` records tracked events for tests. `CheatConsolePresenter` and `SettingsPresenter` take an `IAnalytics`.
- Byte files: `IFileStorage.ReadBytesAsync` and `WriteBytesAsync` read and write raw bytes with the same `NotFound`/`Error` mapping and temp-file replace as the text methods (`InMemoryFileStorage` keeps them in `BinaryFiles`). Implementers of `IFileStorage` must add both.
- `Core.Compression.Deflate`: an edge adapter over raw deflate. `Compress(byte[])` uses `CompressionLevel.Optimal`; `Decompress(byte[], int maxLength)` returns `Corrupted` for invalid data (`InvalidDataException`, or the `IOException` Mono throws) or when the inflated size would exceed `maxLength`, so untrusted input cannot inflate without limit.
- Development-only domains: `DomainDescriptor.IsDevelopmentOnly` (off by default). `ContentDirectoryBuilder` leaves their content directories out unless the build is a development build: `BuildAll(bool isDevelopmentBuild)` takes it explicitly, `BuildAll()` and menu `Build/Content Directories` follow the active Development Build setting (`EditorUserBuildSettings.development`), player builds through the Build Player window follow `BuildOptions.Development`. Descriptor validation (names, `EditorContent`) still covers them in release builds. Register and launch such domains under `#if UNITY_EDITOR || DEVELOPMENT_BUILD`.
- `Bootstrap.BootCoverView`: an opaque overlay canvas (`BootCover`, sort order 32000) in the root prefab, registered by `RootLifetimeScope`.
- `LoadingScreen.WaitForViewAsync`: completes once a Loading view is attached (at once if one already is); throws `OperationCanceledException` when the screen is disposed first.
- Cheat console (Editor and development builds only, `UNITY_EDITOR || DEVELOPMENT_BUILD`): a `CheatConsole` overlay canvas (sort order 30000) in the root prefab with `Core.Cheats.CheatConsoleView`, registered by `RootLifetimeScope`. Backquote toggles it; while typing, a suggestion list attached under the input shows the matching names and values: Up/Down move through it (or recall history when no list is shown), Tab or Enter accept the highlighted one, Tab without a highlight autocompletes, Escape hides the list first and closes the console when none is shown; built-in `help [cheat]` and `clear`. Cheats implement `ICheat` or `ICheatProvider` (`CheatCommand`), declare `CheatParameter`s and are registered per scope with `builder.RegisterCheat<T>()` / `builder.RegisterCheats<T>()`. Agents call `CheatConsoleView.Submit(line)` and read `LastReply`; `Submitted` carries those lines, `Entered` the lines typed and confirmed with Enter. Release builds deactivate the console object.
- Looping SFX: `IAudioService.PlayLoop(AudioCue)` plays a 2D loop on one of the authored SFX sources and returns a `Core.Audio.AudioLoop` handle (`IsPlaying`, `Stop`, `Dispose`). `default(AudioLoop)` is a silent handle; `Stop`/`Dispose` are idempotent and never touch a newer sound on the same source; the service's `Dispose` stops every loop. The cue must have `Loop` set (`PlayLoop` throws otherwise, as `Play` still throws on a looping cue) and plays through its mixer group, so it follows the SFX and Master volumes. Loops are never reclaimed as finished; when every source is busy, the oldest one-shot is stolen first and a loop only when all sources hold loops (that loop's handle goes silent). Implementers of `IAudioService` must add `PlayLoop`.
- `GameInput` `UI/Zoom`: a 1D axis (Value, Axis) bound to `=`/`-` and numpad `+`/`-` (Keyboard&Mouse) and the right/left triggers (Gamepad); positive zooms in. The mouse wheel stays on `UI/ScrollWheel`. Implementers of `GameInput.IUIActions` must add `OnZoom`.
- `GameInput` `UI/ToggleView`: a Button bound to `T` (Keyboard&Mouse) for switching between two views of a screen. Implementers of `GameInput.IUIActions` must add `OnToggleView`.
- `GameInput` `UI/Details`: a button bound to `I` (Keyboard&Mouse) that opens or closes a details/info panel. Implementers of `GameInput.IUIActions` must add `OnDetails`.
- `GameInput` `UI/Peek`: a hold Button bound to Tab (Keyboard&Mouse) and the left shoulder (Gamepad); `performed` on press, `canceled` on release. Implementers of `GameInput.IUIActions` must add `OnPeek`.
- `GameInput` `UI/Shortcut1`, `UI/Shortcut2`, `UI/Shortcut3`: buttons bound to the number row and numpad `1`/`2`/`3` (Keyboard&Mouse) for screen-specific shortcuts. Implementers of `GameInput.IUIActions` must add `OnShortcut1`, `OnShortcut2` and `OnShortcut3`.
- `GameInput` `UI/Confirm`: a Button bound to Enter and numpad Enter (Keyboard&Mouse) for committing a screen's primary action, separate from `UI/Submit` (which also fires on Space and gamepad South). Implementers of `GameInput.IUIActions` must add `OnConfirm`.
- `GameInput` gains a `Debug` map (`ToggleConsole`, `CloseConsole`, `CompleteCommand`, `PreviousCommand`, `NextCommand`); `InputService` keeps it enabled in Editor and development builds, outside the `InputMaps` stack.
- `Core.asmdef` references `R3.Unity` and `UnityEngine.UI` (both already required by the package).
- UI interaction sounds: `Core.Audio.UiInteraction` (Hover, Click, Back, Step, Tick), the seam `IUiInteractionSounds` that the game module implements (`RootLifetimeScope` registers the silent `NullUiInteractionSounds` when the game module registers none), `UiInteractionRelay` on a canvas root plus `builder.RegisterUiInteractionSounds(relay)` in the screen's scope (a per-scope presenter forwards each interaction; slider ticks are throttled to one per 75 ms), and `Shared.UI.UiInteractionEmitter` (hover on pointer enter when interactable, click through `Button.onClick`, so Submit sounds too). `Button.prefab`, `Selector.prefab` (Previous/Next click as Step) and `Slider.prefab` (hover only) carry emitters; `SliderView` emits Tick on user changes, never on `SetValue`; the Settings scene has a relay and its Back button plays Back.

### Changed

- Content directories are built as one LZ4HC-compressed archive each (`BuildContentOptions.UseArchive`, `BuildCompression.LZ4`) without type trees (`DisableWriteTypeTree`, with `SerializeUnityVersion`), which cuts their size to about a quarter. A player only reads content built by the same Unity version and build: rebuild content built by an older package version (every player build does). The `Built content directory` log line now reports the directory size. No public API, persisted data or asset change.
- The package scenes (`Bootstrap`, `Loading`, `Consent`, `Settings`) use no skybox: no skybox material, a flat ambient colour, custom environment reflection with no cubemap, and a baked lighting data asset (`<Scene>/LightingData.asset`, no lightmaps). Builds no longer pack the default procedural skybox, its shader and a generated 128 px reflection cubemap (about 0.5 MB) for these scenes. The scenes are UI-only, so they look the same.
- Content directories: `ContentDirectoryBuilder` builds the content of every domain into one shared directory (`Content/Shared`, `ContentDirectoryBuilder.SharedDirectoryName`), so assets used by several domains are stored and loaded once instead of once per domain. Each built directory's only root is a generated `Core.Content.ContentCatalog` (entries `ContentCatalogEntry(Name, Content)`), created as a temporary asset under `Assets/ContentCatalogBuild` during the build and deleted afterwards (gitignore it). `ContentDirectoryRegistry` reads the catalog of every registered directory and finds a domain's `DomainContent` by its descriptor's `ContentDirectoryName`, which now names the domain's content (its catalog key) and is its directory name only for a domain with its own directory. A directory without exactly one catalog logs an error and is skipped; a content name in two directories throws. New `DomainDescriptor.HasOwnContentDirectory` (default off) builds that domain into its own directory (e.g. separately shipped content); its name may not be `Shared`. Development-only domains join the shared directory in development builds and are left out of release builds. Every `DomainContent` now loads when the content is registered at boot, together with its direct (non-`Loadable`) references: keep content assets to `LoadableSceneId`/`Loadable<T>` fields. `DomainRunner`'s missing-content errors name the content instead of the content directory. Built content is regenerated by every player build; no public signature or persisted data changes.
- Settings hides its Language row (`SettingsView.SetLanguageVisible`) while `CoreConfig.SupportedLanguages` holds a single language; it shows with two or more.
- Telemetry never loads, writes or sends anything in the Editor unless `EditorReportingOverride` is armed for the Play session; `TelemetryPipeline`'s constructor takes a `ReportingRule`.
- `DomainRunner`'s constructor takes an `AnalyticsFlushSignal`.
- `ApplicationService` is an entry point (`IInitializable`, `IDisposable`) that owns the single `Application.wantsToQuit` gate; `SaveAutoFlush` flushes the save store through `AddQuitHandler` (with `CancellationToken.None`, so the budget never cuts a local save) instead of hooking `wantsToQuit`/`quitting` itself. Save-on-quit behaviour is unchanged.
- Analytics is no longer behind the `ANALYTICS_ENABLED` scripting define; projects that set it can drop it (no effect).
- `GameInput` `UI/Submit` also binds `<Keyboard>/space` (next to `*/{Submit}`), so Space triggers `IUIActions.OnSubmit`. uGUI's EventSystem uses its own actions, so Space does not click selected buttons.
- Package EditMode tests pruned: tests without a meaningful assertion, tautologies, duplicates and redundant parameter rows removed (Core.Tests, Bootstrap.Tests, Loading.Tests, Shared.UI.Tests); no production code changed. The boot cover layout check compares offsets with a tolerance.
- `Core.Settings.SettingsService` split internally: core-settings DTO conversion and validation moved to `CoreSettingsNormalizer`, domain-section storage to `SettingsSectionStore` (both internal). No public API or `settings.json` format change.

### Removed

- **Breaking:** Polish, the template's example second language, is gone; English is the only language. `Language.Polish` (value 2), the `_polish` column of `LocalizationEntry` and its `GetText`, `GetCulture` and `GetNativeName` arms are removed, `CoreConfig.SupportedLanguages` defaults to and ships with `[English]`, and the package tables (`SharedText`, `LoadingText`, `SettingsText`, `ConsentText`) lose their Polish values. Code that names `Language.Polish` no longer compiles; serialized `_polish` values in a game's tables are ignored by Unity and dropped on the next save of that table.

### Fixed

- `AudioService` routes a cue whose mixer group belongs to a copy of the registered mixer (same mixer name, another instance, as when content directories and player data both reference the mixer in a player build) to the registered mixer's group of the same name, so volume settings apply to sounds loaded from content directories. A group name the registered mixer lacks (or has twice) keeps the authored group and logs one `Audio` warning per name; groups of differently named mixers play as authored. New log tag `Audio`.
- Consent scene: the title no longer touches the close button (title width 736), so `ConsentSceneTests.Layout_BackdropBlocksCanvasAndCloseSitsInPanelClearOfTitle` passes regardless of float rounding.
- Consent prompt and Settings Privacy row no longer call the data anonymous: data is pseudonymous (linked to a random install id) and crash reports carry device details. `ConsentText/body` now reads "May we send gameplay data and crash reports to help improve the game? They are linked to a random ID, not to your name. You can change this at any time in Settings." and `SettingsText/send_data` "Send gameplay data and crash reports". Keys are unchanged.
- Settings scene: the panel lays out in one pass. Its `VerticalLayoutGroup` now controls child heights (`LayoutElement` heights on `Title` and `Back`) and the Privacy row loses its nested `ContentSizeFitter`, which left the row at height 0 on the first layout pass, overlapping `Back` and failing `SettingsSceneTests.PrivacyRow_SitsInsidePanelBelowLanguageAndPanelFitsReferenceHeight`. The row still shrinks when the deletion hint is hidden.
- Leaving Play mode or quitting while a domain ran logged `MissingReferenceException`s: Unity destroyed the domain's views before the scope's `OnDestroy` disposed its container, so `Dispose` code and the callbacks it triggered (an input lock released into its subscribers, an observable reset) touched destroyed objects, and the first exception aborted the rest of the disposal, leaving tickables running. `DomainLifetimeScope` now disposes its container in `OnApplicationQuit`, while every scene object is still alive, and `DomainRunner`'s teardown skips the scene-set unload of a scope disposed that way.

- The first frames after launch showed the empty boot scene (the root camera's skybox) until the Loading scene had loaded. The boot cover now covers them from the first frame; `GameFlow` hides it in the frame the Loading view attaches, already visible. Debug-domain and PlayMode test boots hide it at once.
- A domain run with `Transition.Loading` revealed the screen before the sub-domains it starts during startup had loaded (empty frames between the reveal and the sub-domain's scene). `DomainRunner` now counts a domain's readiness as including those sub-domains: the loading screen also waits for their scope scenes, content loads and first `Start`. Sub-domains started after the reveal are unaffected.

### Migration

- Polish removal: replace `Language.Polish` in game code and tests (tests that switched languages have nothing to switch to; drop them or drive `ILocalizationService.Current` through a substitute), remove `Polish` from a game's own `CoreConfig` supported list, and strip `_polish:` lines from game tables (or re-save them in the Editor). A player's `settings.json` that stores `"language": "Polish"` loads as English: the core settings normalizer treats the unknown name as an invalid value, logs one warning and rewrites the file. No format version change.

## [1.1.0] - 2026-10-02

### Added

- `GameModule.IsUiNavigationEnabled` (off by default): turns on keyboard/gamepad UI navigation on the root EventSystem. `RootLifetimeScope` applies it at boot.
- Game-owned boot scene: **Tools > Foundation > Create Game Module** also creates an empty `Assets/_Project/<Game>/Scenes/Boot.unity` and puts it first in Build Settings, replacing the package's `Bootstrap.unity`, which a game consuming the package from git cannot open.
- **Tools > Foundation > Create Boot Scene** (`Bootstrap.Editor.GameBootScene.CreateForActiveModule`) migrates an existing game: it creates `Scenes/Boot.unity` next to the active game module's `VContainerSettings` and swaps the Build Settings entry. Safe to run again.
- A `Bootstrap.Tests` EditMode test fails when the Build Settings boot scene holds GameObjects, and player builds warn about it: app-lifetime objects belong in the root prefab.
- `BootstrapScene.PackagePath`, `FindBootPath`, `PlaceFirst`, `CountGameObjectsAt` and `CountGameObjects`.

### Changed

- The root prefab's EventSystem no longer sends navigation events (Move/Submit/Cancel) by default, so Enter, Space or gamepad South no longer re-click the last clicked uGUI button. Games that use keyboard or gamepad UI navigation tick `IsUiNavigationEnabled` on their game module asset.
- Debug runs from a scope scene boot through the first enabled Build Settings scene and fall back to the package's `Bootstrap.unity` when none is listed (they logged an error before). The package scene is kept only as that fallback.

### Migration

- Games set up on 1.0.0 keep working unchanged. To own the boot scene, run **Tools > Foundation > Create Boot Scene** once and commit the new scene and `ProjectSettings/EditorBuildSettings.asset`.

## [1.0.0] - 2026-10-01

### Added

- First release as a package, extracted from the Unity project template: Core (domain runner, scopes, save store, settings, input, audio, localization, content directories, logging), Shared (UI widgets, TestUtils), Bootstrap (root prefab, default `VContainerSettings`, `Bootstrap.unity`, play-from-any-scene), and the Loading and Settings domains, with their tests.
- Editor tools: `Tools/Foundation/Create Game Module`, `Tools/Foundation/Use Package From Git`, `Tools/Input/Generate GameInput`, `Tools/Localization/Generate Text Keys`, `Build/Content Directories`.
